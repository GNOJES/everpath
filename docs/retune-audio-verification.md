# v0.4.0 성장·사운드 검증

2026-11-18.이 문서는 v0.3의 쉬운 첫 클리어를 개선한 최신 기록이다. 이전 보고서는 당시 조건의 기록으로 남긴다.

## 변경

영구 강화4종을 각10→20레벨로 세분화했다. 공격/HP는 레벨당12→6%, 이동2→1%, 골드5→2.5%다. 최대 보너스는 유지한다. 가격은 `24 + 12L + 3L²`로, 같은 보너스를 빠르게 사는 비용이 커지고 높은 단계까지 꾸준히 투자해야 한다. 기존 저장은 progressionEconomy2로 한 번 변환하여 구매 레벨을 두 배로 바꾸고, 골드/투자액/기록/해금을 유지한다. 초기화 시 환불액도 실제 투자액을 사용한다.

마법사 피해28→24, 연쇄 번개1.4→1.2배, 화염2.1→1.8배. 냉기 둔화는 일괄45%에서 랭크별24/30/36%로 조정했다. 초기 광역·둔화로 경험치와 생존을 동시에 확보하던 효율을 낮췄다. 최종 보스HP36,000→56,000으로 올려 도달 이후에도 진화·공격·생존 성장이 필요하도록 했다. 등장10분/결계 제한100초는 유지하며 구매 레벨에 따른 무적·강제 실패 조건은 없다.

## 모의 시험

정상HP, 전투 상태 수정 없이 시뮬레이션30Hz·판단10Hz. 성장 비교는 영웅3×성장0/5/10/15/20×시드6(42,271,2026,91,777,4096)×빌드3(무기/균형/스킬) = **270회**다. 각 칸은18회 중 클리어 수와 평균 생존/클리어 시간(초)이다.

| 영웅 | 성장0 | 성장5 | 성장10 | 성장15 | 성장20 |
| --- | --- | --- | --- | --- | --- |
| 전사 | 0 / 262 | 0 / 308 | 0 / 367 | 2 / 567 | 8 / 618 |
| 궁수 | 0 / 287 | 0 / 359 | 0 / 436 | 3 / 512 | 8 / 587 |
| 마법사 | 0 / 246 | 0 / 303 | 1 / 414 | 2 / 445 | 9 / 545 |

새 저장에서 획득 골드만 사용한 연속 시험은 영웅별16경로: 무기/스킬 빌드×균형/공격 우선 구매×시드 순환 시작점4개다. 실패 원정과 구매 내역을 모두 남겼다. 총 **48개 캠페인·768회 원정**이므로 성장 비교와 합쳐1,038회다. 별도의 기존 정지/순환/회피81회 검사도 유지한다.

| 영웅 | 첫 클리어 최소 | 중앙값 | 최대 | 성공 경로 |
| --- | --- | --- | --- | --- |
| 전사 | 12회차 | 18.5회차 | 22회차 | 16/16 |
| 궁수 | 8회차 | 14회차 | 26회차 | 16/16 |
| 마법사 | 5회차 | 12.5회차 | 31회차 | 16/16 |

모든 측정 경로에서2회차 클리어는 사라졌다. 영웅별 첫 클리어 중앙값 비율은1.48배로 검사 상한1.6 이하다. 성장0·5는 세 영웅 모두 클리어0회다. 한 원정의 결과는 시드·강화 선택에 따라 이전보다 짧을 수 있지만 성장 단계별 평균 도달 시간은 증가한다.

이 수치는 자동 조작의 재현 가능한 표본이며 사람의 첫 클리어 횟수/성공률 보장이 아니다. 48경로도 시드를 순환하므로 서로 완전히 독립된 확률 표본은 아니다. 드문5회차 성공을 막기 위해 구매 장벽을 넣는 대신, 검사 기준을 최소5회/영웅별 중앙값8~20/중앙값 비율1.6미만으로 정했다. 어려운 마법사 스킬·공격 우선 경로는30회에서 미완료였고31회에 성공했다. 이를 누락하지 않고36회 검사 한도 안에 기록했다.

원본: [campaign-growth.json](playtests/campaign-growth.json), [retry-economy.json](playtests/retry-economy.json). 이전 원본은 파일명에 `-v030`을 붙여 보존했다. 중간 실험에서 마법사 피해21은 한 경로가 정체되어 채택하지 않았다. 최종 수치로 전체 검사를 다시 실행했다.

## 사운드 점검

직접 출력하던 음을 음악/효과음 버스로 나누고 마스터 압축기를 연결했다. 슬라이더와 음소거는 이미 재생 중인 음에도 적용된다. 음악은 일시정지·선택 메뉴에서 빠르게 감쇠하고, 네이티브 중단은 예약된 음까지 정지한다. 레벨업 예약을 JS 타이머에서 AudioContext 타임라인으로 옮겨 중단 후 뒤늦게 울리는 소리를 방지했다. 활성 발성은24개로 제한한다.

음악 출력 레벨을 보강하고 클릭·무기·명중·플레이어 피격·보스 출현·승리·패배 신호를 구분했다. 효과음에서 Math.random을 제거하여 사운드 설정이 전투 난수에 영향을 주지 않는다. 외부 음원은 사용하지 않는다.

tests/audio.test.ts는 실시간 버스 음량/음악 일시정지/예약음 중단/재개/발성 상한/난수 독립을 검사한다. e2e/audio.spec.ts는 **실제 OfflineAudioContext DSP**로 여러 효과를 합성하여 유한 PCM, RMS>0.001, 최대 피크<1, 음소거 후 RMS<0.0001을 검사한다. 브라우저의 실제 AudioContext가 nativePause 후 suspended, 재개 클릭 후 running이 되는 것도 확인했다. 폰 스피커로 청취하거나 음질을 보증한 검사는 아니다.

## 검증 결과

- `npm test`: **85개 /16파일 통과**. 전체 성장 행렬과48개 재도전 경로를 포함한다.
- `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`: **12개 통과**. 사운드2개, 성장/환불/수치 표시, 세 영웅·터치·저장·진단·네이티브 메뉴 회귀를 포함한다. 골드2.5%를3%로 반올림하던 표시도 회귀 검사 후 수정했다.
- `PLAYWRIGHT_CHANNEL=chrome npm run test:campaign-browser`: 정상HP 최대 성장 마법사/실제 CDP 터치/가속 시계로 **619.390초에 클리어**, 남은HP27.57,1313처치, 보스3, 최대 장면 오브젝트165, 페이지 오류0. 패배 직전까지 자원을 사용하고 승리·정산·도전 해금을 확인했다. 원본 browser-campaign-grown-mage.json은 현재 v0.4 결과다. 시계 가속 FPS를 폰 성능으로 해석하지 않는다.
- APK0.4.0/versionCode4를 타입 검사→웹 빌드→Capacitor sync→Gradle→apksigner로 재빌드한다. 최종 SHA/크기는 artifacts/android/build-info.json과 체크섬 파일을 기준으로 한다. 기존 패키지·서명은 유지한다. 이번 작업에서 물리적Android 폰 청취/설치 검사는 하지 않았다.
